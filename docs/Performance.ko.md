# 성능

## 측정 환경과 방법

| 항목 | 값 |
|---|---|
| 측정일 | 2026-11-11 |
| CPU | Intel Core i7-14700K (논리 코어 28) |
| 메모리 | 64 GB |
| 그래픽 | NVIDIA GeForce RTX 4080 SUPER |
| OS / 화면 | Windows 11 Pro / 1920×1080 |
| 빌드 | Release x64, .NET Framework 4.7.2 |

- 뷰어 크기 1920×1080(화면 전체), 영상은 미리 만들어 둔 두 장을 번갈아 넣음(영상 생성 시간 제외).
- 입력 스레드 하나가 목표 속도로 `SetImage`를 2초간 호출하고, UI는 실제 프로그램과 같은 메시지 루프로 동작.
- **복사** = `SetImage` 한 번에 걸린 평균 시간(호출 스레드). **그리기** = `OnPaint` 평균 시간(UI 스레드).
- **건너뜀** = 더 새 프레임에 밀려 화면에 그리지 않은 비율.

재측정: `VisionImageViewer.Checks.exe bench` (약 2분). 원본 출력은 [bench-raw.txt](bench-raw.txt).

> **개발 PC에서 잰 값입니다.** 현장 검사 PC는 CPU와 메모리 속도가 달라 수치가 달라집니다. 적용할 PC에서 다시 측정하세요.

### 500 fps 입력 (화면보다 훨씬 빠른 입력)

화면 표시는 120~270fps에서 멈추고 나머지는 건너뜁니다(32~63%). 의도한 동작입니다.
모니터가 60Hz라 그 이상 그려도 눈에 보이지 않고, 뷰어는 UI 스레드를 절반 이상 비워 두도록 그리기 간격을 둡니다.
큰 영상(8192×4096 컬러, 16384×4096 흑백)은 복사 시간(3.5~5.5ms) 때문에 입력 자체가 170~270fps로 제한됩니다.

## 읽는 법

- **그리기 시간은 영상 크기와 거의 무관**합니다(2048² 2.8ms ↔ 16384×4096 2.6ms). 화면에 보이는 픽셀만 처리하기 때문입니다.
- **복사 시간은 영상 크기에 비례**합니다(이 PC에서 약 19GB/s). 이 시간은 `SetImage`를 부른 스레드가 씁니다. 8192×4096 컬러(100MB)는 5ms 정도입니다.
- 흑백 1:1이 가장 빠릅니다(1.8ms). 프레임 버퍼에서 화면으로 변환 없이 바로 그리는 경로입니다.

## 개발 중 바꾼 것 (측정 근거)

| 문제 | 측정 | 조치 | 결과 |
|---|---|---|---|
| 24bit 컬러 그리기가 느림 | 1080p에서 11~17ms, 60fps에서 6~18% 건너뜀 | 보이는 픽셀만 32bit 버퍼로 옮겨 그림 | 3~4ms, 건너뜀 0% |
| 큰 흑백 영상의 화면 맞춤 | 16384×4096에서 6.9ms (영상 크기에 따라 증가) | 축소도 보이는 픽셀만 골라 그림 | 2.6ms (크기 무관) |
| 프레임이 쉬지 않고 들어오면 UI 스레드가 그리기만 함 | 창 하나 열고 닫는 데 1.2초 | 직전 그리기 시간만큼 쉬는 간격 규칙 | 7.6ms |

## 메모리와 핸들

`VisionImageViewer.Checks.exe soak <프레임 수>`: 1024×768 흑백 + 오버레이 2개를 한 스레드가 최대 속도로 넣으면서
워밍업 뒤와 종료 시점을 비교합니다.

| 프레임 수 | 관리 힙 증가 | 프로세스 메모리 증가 | GDI / USER 개체 증가 | 실행 중 2세대 GC |
|---|---|---|---|---|
| 100,000 | 937 KB | — | — | — |
| 300,000 | 937 KB | — | — | — |
| 1,000,000 | 942 KB | 56 KB | 0 / 1 | 0회 |
| 3,000,000 | 934 KB | — | — | — |

- 관리 힙 증가분이 프레임 수와 무관하게 약 0.94MB로 같습니다. 프레임마다 쌓이는 누수가 아니라 측정 구간 안에서 한 번 생기는 할당입니다.
- 100만 프레임 동안 GDI 개체 증가 0, 2세대 GC 0회였습니다.
- (—) 칸은 그 실행에서 기록하지 않은 값입니다. 판정은 모두 통과였습니다.

## 한계

- 모니터 주사율보다 빠른 입력은 전부 보이게 할 수 없습니다. 건너뛴 수는 `Statistics.Skipped`로 확인합니다.
- `ZoomOutQuality.Smooth`는 원본 전체를 읽어 평균하므로 큰 영상에서 느립니다. 이 문서의 수치는 `Fast` 기준이며 `Smooth`는 측정하지 않았습니다.
- 오버레이가 수백 개 이상일 때의 그리기 시간은 측정하지 않았습니다.
- 4K 모니터 전체 크기 뷰어는 측정하지 않았습니다. 그리기 시간이 화면 픽셀 수에 비례하므로 1080p의 약 4배로 예상됩니다(추정).
- 현장 PC, 원격 데스크톱 환경에서는 측정하지 않았습니다.
